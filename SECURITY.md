# Security Policy

## Supported versions

Security fixes go to the latest stable version and the `master` branch.
Older releases do not get fixes, so upgrade to a supported version.

| Version        | Supported          |
| -------------- | ------------------ |
| Latest stable  | :white_check_mark: |
| master         | :white_check_mark: |
| Older releases | :x:                |

## Reporting a vulnerability

Please do **not** open a public issue for security problems.

Instead, use the **GitHub Private Security Advisory**:
[Open a draft advisory](https://github.com/kapicorp/kadet/security/advisories/new).

Include as much detail as possible:

- Affected versions
- Steps to reproduce
- Potential impact
- Suggested fix (if you have one)

## Response process

- We aim to acknowledge reports within 5 business days.
- We will provide an initial assessment within 15 business days.
- Once a fix is ready, we will coordinate disclosure and publish a security advisory.
- We credit reporters unless they prefer to remain anonymous.

## Disclosure policy

We follow a coordinated disclosure model. We ask reporters to give us reasonable
time to release a fix before publicly discussing the issue.
